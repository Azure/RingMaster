# Design Note: Generate and Publish Code Coverage 

## Introduction 

Code coverage is a measure of how many lines/blocks/branches of the source code are executed in the tests. As part of 
the code yellow effort to improve code quality, we need to generate code coverage summary in the build pipeline. Vega 
uses CDPx, a next-generation engineering pipeline that enables teams across Microsoft to ship code across all platforms. 
This note shows how to generate and publish code coverage summary for Vega in CDPx. 

## Steps to Enable Code Coverage 

1. DotNet Test SDK and MSTest need to be updated to latest version, as old versions may not support code coverage. Below 
are the versions we will use: 

```
  <PackageReference Include="Microsoft.NET.Test.Sdk" Version="15.9.0" /> 
  <PackageReference Include="MSTest.TestAdapter" Version="1.4.0" /> 
  <PackageReference Include="MSTest.TestFramework" Version="1.4.0" /> 
```

2. Generate code coverage during test run. 

We found two approaches to generate code coverage during test tun. First is using an open source tool called 
[Coverlet][1] which will generate code coverage in cobertura format that CDPx supports. However we also found that the 
code coverage number generated by Coverlet is often not accurate. For example even though we have lots of test on 
RingMasterBackendCore component, running RingMasterBackendCoreUnitTests with Coverlet shows 0 coverage. It maybe due 
to how the tests are structured, but we can not afford to change our tests. So we decided to use the second approach. 

The second approach is to generate code coverage with native vstest. It will generate a .coverage file which is not only 
more accurate, but also contains more information than the one Coverlet generated, such as block coverage. Then we 
created a code coverage tool that can merge the .coverage files from different test run to convert to XML format. 
Another open source tool called [ReportGenerator][2] is used to convert the XML to Cobertura format as well as HTMLs. 

3. Upload the coverage reports to CDPx. 

According to the [CDPx documentation][3], in the yml file where we specify the build and test actions in the pipeline, we 
need to add additional code coverage command like this: 

```
  codecoverage:
	  - summary_file: 'CoverageReport\Cobertura.xml'
		report_directory: 'CoverageReport'
		coverage_tool: 'Cobertura'
		include:
			- 'CoverageReport\Cobertura.xml'
```

Note that although we didn't specify any HTMLs in the above command, they do need to exist in the CoverageReport folder 
prior to calling this command. 

## Tune the Coverage Report 

The code coverage report will by default include all components in our source code, but there are some test code that we 
don't want to count into code coverage. To solve this issue, we can specify a .runsettings file when we run the tests, 
which can be used to specify which components need to be include/exclude in the coverage report. More information on the 
runsettings file please refer to [this][4].

## Debugging in CDPx Environment 

To debug any issues we run into in CDPx pipeline(e.g. build/test failures), we need to have the same environment as 
CDPx. The OS image we use in CDPx pipeline is specified in the yml file. The image need to run in a docker container. 
See [this][5] documentation on how to access and run the container image locally.
