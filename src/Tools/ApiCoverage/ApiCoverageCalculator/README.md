# API Coverage Tool

## About this Tool
This tool is used for calculating unit test coverage of public WCF API contract interface functions. 

The only basic logic is
1. Get list of WCF API interface functions with `OperationContract` attribute.
2. Get unit test coverage info from `.coverage` file generated by VSTS

## Input of this tool
1. .dll assembly file
2. .coverage file corresponding to the assembly in 1)

## Output of this tool
This tool will generate a result.csv file under the `ApiCoverageCalculator` folder.

This file contains 4 columns:
1. Interface fullname
2. Method name
3. Is this function covered
4. Parameters of the function, separated by ';'

_i.e: Due to limitation of .csv, more columns can present if the paramaters contains ",". For example, Dictionary<A,B> will make a separate column of B>_

## Supported Platform
.net framework 4.6.2 / .net core 2.1

x64 only

## How to use this tool
### Entry Point
This tool is self contained, after you configure the `CalculationRequests.json` file, simply invoke `ApiCoverageCalculator.exe` under `{net462|netcoreapp2.1}/ApiCoverageCalculator` folder.

### Configuration
All the request information live in `CalculationRequests.json` under `ApiCoverageCalculator` folder.

A typical file looks like this:

```json
{
  "CalculateRequests": [ // This object contains the implementation assemblies
    {
      "DllFileName": "A.dll", // This is the dll file name
      "CoverageFileName": "C:\\.....\\...A....coverage", // This is absolute path to the coverage file.
      "AssemblyFolder": "F:\\" // This the folder where the dll as well as all of its dependencies lives
    },
    {
      "DllFileName": "...",
      "CoverageFileName": "...",
      "AssemblyFolder": "..."
    },
    //...
  ],
  "InterfacesToIgnore": [], // Interfaces to ingore, not yet implemented
  "InterfaceWrappers": { // This object contians Interface wrappers pair, will explain further below 
    "Microsoft...FakeInterface": { // This is the implementation interface
      "InterfaceName": "Microsoft...IFakeWCFInterace", // This is the WCF interface
      "AssemblyName": "x.dll" // This is the WCF interface definition assembly
    },
    // ...
  }
}
```

### Framework
This tool relies on reflection to findout API functions, so there may be cases when .net framework and .net core cannot reference each other due to missing dependencies.

Pick the framework matchs the assembly being calculated.

## Interface wrapping
_(This is an unusual case and probably mean that you want to fix your unit test to invoke WCF API directly)_

In some cases like below:
```c#
[ServiceContracts]
public interface IWCF{
    [OperationContract]
    void TestMethod();
}

public interface IRealLogic{
    void TestMethod();
}

public class WCF : IWCF{
    private RealLogic realLogic;
    public void TestMethod(){
        // This class only invokes other function
        realLogic.TestMethod();
    }
}

public class RealLogic{
    public void TestMethod(){
        ...
    }
}
```

If the unittest covered methods in `RealLogic` class (IRealLogic interface). It may well mean that the APIs has also been covered.

### Restrictionctions
The method signature between `IWCF` and `IRealLogic` need to be the same, specifically:
1. Method name need to be same
2. Parameter types need to be the same (also need to be in same order)
